# POF 发布与更新

## 文件上传位置

| 内容 | 上传位置 | 什么时候需要更新 |
| --- | --- | --- |
| Windows 安装包 | `Baozi-Pei/POF-Releases` → Releases → 发布版本的附件 | 每次发布软件新版本 |
| 便携 ZIP | 同一 Release 的附件 | 需要提供便携版时 |
| 网页、使用手册和截图 | 本仓库 `main` 分支 | 修改网页或手册时 |

仓库地址：https://github.com/Baozi-Pei/POF-Releases

## 首次上线

1. 将网站文件推送到仓库 `main`。
2. 打开仓库 **Settings → Pages**，把发布来源设为 **GitHub Actions**。
3. 在 **Actions → Publish POF website** 中确认部署成功。
4. 访问 `https://Baozi-Pei.github.io/POF-Releases/`，检查首页和使用手册。
5. 按下述步骤发布第一个软件版本，再验证实际下载。

上述是首次配置步骤。后续网页提交到 `main` 后会自动部署。

## 发布软件新版本

1. 先更新软件内部版本号并重新打包。例如当前 `0.2.0`，下一版可以使用 `0.2.1`。
2. 打开仓库 **Releases → Draft a new release**。
3. 创建对应版本标签，例如 `v0.2.1`；使用标准的三段版本号。
4. 填写版本标题和本次更新说明。
5. 上传安装包，文件名必须保持为 **`POF-Workbench-Setup.exe`**。
6. 如需便携版，再上传 **`POF-Workbench-Portable.zip`**。
7. 等附件完整上传后，发布为正式版本。需要面向普通用户时，不要标为预发布；确认 GitHub 将其设为 Latest。
8. 打开网站确认显示新版本，并实际下载一次。检查安装包大小和 SHA-256 与本地发布文件一致。
   同时将已核验附件的版本、文件名、大小、SHA-256 和直接下载地址写入网站 `downloads.json`，并更新首页的直接下载链接。待正式附件可公开下载后再部署网页；不要将草稿或尚未上传完成的地址放到网页中。
9. 使用旧版本软件检查更新，确认能发现新版本并完成后台下载。自动安装会等待软件正常退出，不应打断正在运行的工作。

软件自动更新使用 GitHub 返回的附件大小和 SHA-256。没有完整安装包、版本号不符合要求、版本不更新或校验信息尚未就绪时，更新不会被直接安装。

## 更新网页或手册

网页内容提交到 `main`，GitHub Actions 会重新部署。手册在线版位于 `manual/index.html`，截图位于 `manual/manual-images/`，下载版位于 `manual/POF-Workbench-Manual.zip`。修改手册时应同步更新在线版、截图和下载版。

网站会自动读取最新 Release。GitHub API 不可达或限流时使用本站的已验证发布信息，因此每次正式发布仍应同步更新 `downloads.json` 和首页兜底地址。网站脚本、依赖模块和发布信息带部署版本，避免新旧缓存混用。

## 当前验证范围

2026 年 11 月 13 日发布 v0.3.4，包含 ECHO 自适应金字塔及布局修复。自动更新增加官网 `downloads.json` 备用入口：本机 GitHub 匿名 API 确认返回 403 限流，Qt 更新控制器实测可切换官网并识别正式发布信息。19 项更新测试通过，覆盖版本判断、损坏下载拒绝、退出后安装交接、未保存工作保护及接口失败回退。打包后的 GUI/worker 共 106 个关键模块与源码核对一致，程序启动检查通过，便携 ZIP 全量 CRC 检查通过。附件大小及 SHA256 与 GitHub 上传记录核对；此轮未完成旧版安装目录上的完整自动覆盖安装，不应将单元测试与联网检查表述为实机升级全链路验收。

旧版更新模块只使用 GitHub API。网络正常但 API 被限流时，旧版可能需要稍后检查更新或手动安装一次新版；0.3.4 起可使用官网备用信息。所有版本仍需要能访问 GitHub 安装包下载域名。

2026 年 11 月 12 日发布 v0.3.2，包含训练页排版、Loss 曲线刻度、慢速缩略图读取和按钮文案适配改进。安装包从公开链接完整下载（681,393,138 字节），SHA-256 为 `e76108ec3223721c98b1fd07a8bf500064b68e98d50c3b0cb4b464e5f86bddcf`，与本地及 GitHub 附件记录一致。便携包通过完整 ZIP CRC 检查，大小与远端 SHA-256 核对通过。软件完成 51 项针对性回归测试、12 种布局组合和打包程序启动检查；更新解析器能从旧版识别 v0.3.2，同版本不重复更新。

2026 年 11 月 11 日发布 ECHO v0.3.0。安装包已从公开地址完整下载（681,391,628 字节），SHA-256 与构建产物及 GitHub 附件记录一致。便携包公开链接的文件头检查通过；本地便携 ZIP 已全量检查 CRC。使用独立测试 AppId 验证安装、文件哈希和安装后启动，未替换日常使用的软件。自动更新解析器能从公开接口识别 v0.3.0，同版本不会重复更新。

下载修复增加本站发布信息回退、中英文状态提示和脚本依赖缓存版本。单元测试及浏览器检查覆盖 GitHub API 不可达、限流、全部元数据不可达和禁用 JavaScript 的情况。GitHub 或文件下载域名本身不可达时，仍需先恢复网络连接。
